# 像素流服务启动器

双击本目录的 **像素流服务启动器.exe**，点击 **启动服务**。默认程序、端口和 1920×1080 分辨率已经配置好，不需要另装 Node.js 或启动官方信令脚本。

## 访问方式

启动后把启动器显示的内网地址发给同一局域网内的访问者。本次部署地址是 **http://172.16.11.175:8080/**；如果电脑换网络或 IP 改变，以启动器显示的地址为准。本机也可访问 http://127.0.0.1:8080/。

网页自动连接并静音播放，无需点击画面；需要声音时点击“开启声音”。加载进度按接入、场景启动、视频协商、视频连接、实际首帧这五个阶段推进，不是虚构的模型加载百分比。网页左下角可展开连接统计，查看实际分辨率、帧率、码率和延迟。

场景旋转使用左键拖动；**平移推荐按住 Shift 再用左键拖动**，缩放使用滚轮，复位使用鼠标中键。原来的右键拖动平移仍可用；如果出现蓝色轨迹或“无效手势”，这是浏览器的鼠标手势，应改用 Shift＋左键，或在浏览器设置中关闭该手势。网页顶部“操作说明”可随时查看这些操作。

右侧导航底部的 **＋ / −** 用于缩放，“全仓”恢复全仓视角并取消选中。左上角显示当前仓库 GHS 和当前区域；只有已接入的仓库可选。

右上角支持中文输入及实际场景检索，例如 `AGV`、`叉车`、`FORK-07`、`第2层`。点击结果会平滑定位并打开详情；结果较多时点击“加载更多”，也可用方向键、Enter、Esc。货架托盘可直接检索，无需先点击模型。场景中的物料标识不等于已接入 WMS 的实时 SKU/库存。

## 启动器设置

| 设置 | 行为 |
|---|---|
| 仓库程序 | 选择已启用 PixelStreaming 的 UE5.4 打包程序。默认指向本包内实际游戏 EXE。 |
| 网页端口 | 默认 8080；访问者使用这个端口。启动前检查占用，冲突时提示并保留原有占用程序。 |
| 串流端口 | 默认 8888；仅供本机 UE 连接，不能与网页端口相同。 |
| 渲染分辨率 | 默认 1920×1080；固定服务端渲染分辨率，浏览器等比适配，不因某位访问者窗口变小影响其他人。 |
| 画面质量 | 提供流畅、清晰优先、超清细节三档，默认清晰优先。只调整视频编码预算，不更改所选分辨率。 |
| 按连接数自动分配 | 默认开启；独立模式根据活跃实例数量与实际帧率反馈调整各实例帧率预算。共享模式始终只渲染一套场景，不按观众人数均分帧率。 |
| 打开仓库程序窗口 | 勾选显示本地 UE 窗口；取消后 UE 在后台无窗口渲染。串流必须有 UE 进程运行，不能完全不运行程序。 |
| 共享场景 · 同一视角 | 只启动一个 UE 实例，最多三人看到并操作同一仓库；任意人的操作会同步影响其他人。新配置默认采用此模式；当前已保存的用户配置采用独立模式，启动器会保留该选择。 |
| 每人独立 · 独立视角 | 首次访问时为该会话启动独立 UE 实例，最多三份；各自视角、面板操作互不影响。需要更多 GPU 和显存。 |

更改程序、端口、分辨率、模式或质量前先停止服务。设置保存在 `launcher.config.json`；高级帧率/码率字段也在其中，关闭启动器后可编辑。默认目标为 60 FPS。

## 清晰度与资源分配

| 质量档位 | 最小码率 | 起始码率 | 最大码率 |
|---|---:|---:|---:|
| 流畅 | 8 Mbps | 20 Mbps | 35 Mbps |
| 清晰优先（默认） | 12 Mbps | 35 Mbps | 60 Mbps |
| 超清细节 | 20 Mbps | 50 Mbps | 90 Mbps |

码率是视频压缩的预算，实际接收值会随画面变化和网络状况调整。升级时，旧版默认的 8／20／35 Mbps 自动迁移到清晰优先；旧版自定义码率保留并显示为“自定义”。明确选择“流畅”后，重新打开启动器不会再次升级此档位。

独立模式开启自动分配后，先按“配置目标帧率 ÷ 活跃实例数”设置相同的帧率预算。默认 60 FPS 对应一人 60、两人每实例 30、三人每实例 20；随后结合各实例的实际帧率反馈，逐步探测可承受的共同预算。运行稳定时缓慢提高目标；实际帧率持续明显低于目标时降低预算，并保持一段时间再重新探测，避免频繁上下波动。访问者退出后会重新分配，回到单人时立即恢复配置的目标帧率（默认 60 FPS）。关闭自动分配时，各独立实例均保留配置目标，由硬件负载决定实际能达到多少帧。

这项功能控制的是实例工作量，**不是把 GPU 硬切成二分之一或三分之一**。共享模式复用同一场景渲染结果，增加观众主要增加编码与网络负载，无需将场景目标帧率除以观众人数。60 FPS 是目标，实际帧率仍取决于显卡、场景、其他应用负载及客户端网络和解码能力。

自动分配保持所选分辨率，不会为了提高帧率将 1080p 自动降为更低分辨率。若高分辨率显示器上的文字或细节仍不够锐利，可停止服务后在启动器选择 **2560×1440**，再配合清晰优先或超清细节；这样会增加显存、GPU 和带宽需求，不能承诺仍达到 60 FPS。浏览器按比例显示完整画面，窗口比例不同时出现对称留边属于正常现象。

## 三人上限

一个浏览器标签页对应一个会话。第四位访问者进入时，最早接入者会被断开，看到中文“连接已被替换”提示；被替换页面不会自动抢回名额，刷新也不会抢回。用户主动点击“重新进入”才申请新名额。

短暂断网或刷新有 8 秒恢复窗口，恢复同一会话不改变先入顺序。独立模式的离开会话会回收自己的 UE；第四人接替时先回收最早实例，再创建新实例。关闭启动器或点击“停止”会关闭本次信令服务及其全部 UE/辅助进程，不会按进程名称关闭其他应用。

## 内网设置

本机已放行网页 TCP 8080 和 UE 媒体 UDP 50000–50199，范围限定 **LocalSubnet**。串流信令 8888 和管理接口仅监听本机，不需要对外放行。

换电脑、修改网页端口或更换 UE EXE 后，停止服务并点击“配置内网访问”，允许 Windows 管理员确认。该按钮只更新本启动器的两条规则。路由器的访客网络/AP 隔离或企业网络策略仍可能阻止客户端直连；客户端应使用可互访的同一局域网。

## 已测性能和边界

以下是 2026-10-21 初版部署的实测基线，早于本次清晰度与自动资源分配更新；不代表新设置的验收结果。在 RTX 5060 Laptop 8GB 上以实际打包仓库、真实浏览器 WebRTC 验证：

- 共享三路均为 1920×1080，8 秒采样约 57–62 FPS，预热后首帧约 1 秒。
- 三套独立 1080p 场景末段采样约 23–24 FPS，GPU 约 99%，显存约 7.5GB。此硬件不能承诺三个独立场景都达到 60 FPS；如多人需要同一画面，可选择共享模式以减少重复渲染。当前启动器保留用户选择的独立模式。
- 独立模式已验证：一人打开库存，另一人仍停留总览；第四人替换后维持三套实例；关闭启动器回收全部实例。
- 测试使用本机浏览器的多标签页，同时验证本机地址与实际内网 IP。没有用第二台物理电脑验证其 Wi-Fi、解码和网络策略；其他设备的体验仍需该设备现场验收。

## 日志与迁移

运行日志位于 `logs`，UE 日志位于 `App/Windows/Test/Saved/Logs`。将整个 **GHSPixelStreaming** 目录复制到另一台 Windows 电脑，不要只复制启动器 EXE。目标电脑需要兼容 UE5.4 PixelStreaming 的显卡/驱动；UE 运行依赖安装程序在 `App/Windows/Engine/Extras/Redist/en-us/UEPrereqSetup_x64.exe`。

本目录的 `runtime`、`server`、`player`、`node_modules`、`App` 均为运行必需。第三方许可见 `runtime/LICENSE.txt`、`player/vendor`，固定依赖版本与校验值见 `dependency-pins.json`。
