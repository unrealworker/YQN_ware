# GHS 静态库存与场景绑定

## 当前 CAD 2.4 整仓规划图

以整仓规划 DXF 的 `BLOCK_CODE`、`SEQ`、`BEAM_CODE_01..04` 定位每排、每档及各业务层，用配套工作簿核对各档的原始插入点、梁层代码和托位数。层内三位沿同排档号递增方向编号，反向放置的通道架按实际模型局部列反序。库存快照保留 WMS 原始编号及库存记录。R、SR、T、WALL 对应库区 450、454、481、519。WALL 的档位通过 `location_row` / `location_col` 校验。档内托盘标签方向属于规则推断。

图纸文件名沿用 2.4，图内修订表的最后一条为 2026-10-10 V2.5。168 个柱网点用于将新版英寸坐标对齐现有关卡。货架立面按逐档梁层属性确定可用托位。B 型普通架使用 11 层，通道上方使用 5 层，保留立面图中的顶梁。地堆沿用原场景的三种示意堆高，实际堆高尚无逐托盘数据。

重建顺序为：

1. 用带 ezdxf 的 Python 运行 `Scripts/ghs/extract_cad24_layout.py <DXF>`，再用 `verify_cad24_geometry.py <DXF>` 核对原图几何。
2. 在 Blender 后台运行 `Scripts/ghs/build_cad24_racks.py`。用普通 Python 依次运行 `Scripts/ghs/prepare_cad24_racks.py` 和 `Scripts/ghs/cad24_floor.py`。
3. 在项目根目录使用 Python 和 openpyxl 生成库存关联与明细。

```powershell
python Tools/GHSInventory/build_bindings.py --csv '<库存 CSV>' --cad '<2.4 整仓规划 DXF>' --workbook '<2.4 库位明细 XLSX>'
python Tools/GHSInventory/export_cad_location_info.py --csv '<库存 CSV>' --cad '<2.4 整仓规划 DXF>' --workbook '<2.4 库位明细 XLSX>' --output output/GHS-CAD24
```

4. 在 UE 5.8 完整编辑器运行 `Scripts/ghs/rebuild_cad24_map.py`。它会检查实例变换并保存 GHS 关卡。运行态验收使用 `Scripts/ghs/verify_real_inventory_runtime.py`，以独立游戏进程加载保存后的关卡。

逐位 CSV 包含 CAD 排、档、梁层、库位规格、WMS 编码、数量和 SKU。明细 CSV 保留一库位多条库存记录。地堆以原图 `ZONE_CODE + SEQ` 核验，多个地堆托盘共享整区编码时保留各自独立的 CAD 身份。

## 历史版本 GHS 0.23

输入是用户提供的 2026-11-25 库位库存 CSV、GHS 0.23 原始 CAD，以及项目当前的场景、托位和模型清单。导入器不修改原始输入。本次接入静态导出，不代表实时库存接口。

## 数据与位置分别表示

- CSV 原始库存通过 `warehouse_id + location_id` 查询，保留数量、SKU、库位档案与更新时间。
- CAD 中的 `BLOCK_CODE`、`SEQ` 提供排、档，独立 TEXT 也可能补充物理排号；不能把任意文字或每档编号当作每个托位的完整 WMS 库位码。
- 自动生成的绑定全部为 `confidence: rule_inferred`，即“按规则匹配，未现场核验”。本批次现场确认数为 **0**。真实库存数据不等于物理位置已经现场确认。
- 无唯一映射的场景目标保持未匹配，不能因查无映射判定为空位。地堆不做猜测绑定。

## 本批次规则与结果

1. 读取原始 DXF 实体句柄与 `BLOCK_CODE/SEQ`，核对项目清单的 CAD 身份、位置和模型。
2. 普通货架只接受 `GHS-Rxx-…`，且库区必须为 `450`；SR 只接受 `GHS-SR-xx-…`，且库区必须为 `454`。不合并历史编码族。
3. 第 `SEQ` 档生成三个位置号 `(SEQ - 1) × 3 + C1/C2/C3`。本批次 55 个有效排的档号沿 CAD +Y 递增，模型三列也按这个方向排列；档内现场标牌方向仍属推断。
4. 通道上层根据托盘底部实际高度，对齐同规格完整货架的物理层。A 通道上两层是 3/4；B 上六层是 7–12。不得直接使用通道模型局部层号 1/2。
5. WMS 完整码、库区、档号 `horizontal_num`、层号 `location_layer` 均一致才生成候选。仅在同一个 `GHS-R` 或 `GHS-SR-` 分隔编码族内允许数字段前导零差异，保存 WMS 原完整码；同族数值归一后有多个库位时全部拒绝，不合并 `GHS-SRxx` 等旧编码族。
6. 绑定同时保存原始场景注册清单的完整变换契约：`expectedPositionM` 为 CAD 米坐标，`expectedWorldRotationDeg` 为 UE 世界 `pitch/yaw/roll`，`expectedWorldScale` 为三轴缩放，`expectedMesh` 为完整货位 `_Capacity` 网格。旋转依据 `apply_refinement_v2.py` 的坐标转换，不能从当前已改动姿态重新认定；同一 CAD 身份的冲突变换全部拒绝。
7. 特殊通道先核对原 DXF 属性，再要求两侧最近同轴货架的规格、朝向、排号一致，档号相差 2、距离对称且间距合理。只有 `Sxx` 数字与两侧 `SRxx` 相同才能补排号；R31/R32 通道由两侧第 12、14 档推导第 13 档。原属性保留在 `cadResolution`，不修改 CAD。
8. 编号方向按实际实例中心检查，不使用可能位于反向端点的 INSERT 原点。R40–R47 的 13/14 档存在中心顺序倒置，其中 8 个通道块原始变换反向；涉及 144 个托位暂停绑定，不自动互换编号，其余无冲突档保留。
9. 左端独立 `R1` 文字（句柄 `2379D0`）为匿名竖排提供身份依据。严格核对原文、原点、字形标定、文字样式、可见性及父块变换，只接受同时与 R02、R03 两排同档、同规格、同朝向且中心 Y 重合的 14 档。补 168 个 R01 托位；另 8 档偏移 0.3048 m，继续不绑。底边 R19/R20/R21 实际对应 SR01/SR02/SR03，禁止将底边 R1–R69 全部当成业务排号。

## 更新方法

在项目根目录运行（Python 3.10+）：

```powershell
python Tools/GHSInventory/import_inventory.py --help
python Tools/GHSInventory/build_bindings.py --csv '<库存 CSV 完整路径>' --cad '<原始 DXF 完整路径>'
python Tools/GHSInventory/test_build_bindings.py
python -m unittest discover -s Tools/GHSInventory/tests
```

生成文件 `Content/GHSTwinUI/data/inventory-bindings.json` 记录源文件 SHA-256、规则、推断限制、逐托位绑定和差异数量。更新 CAD、场景或库存后应重新生成；不能复用别的仓库 ID 或丢弃源编码前缀。

三个运行时源清单 `scene-bindings.json`、`rack-slots.json`、`storage-capacity.json` 通过 `.gitattributes` 保留原始字节，避免 Git 自动转换换行后使哈希校验失败。
