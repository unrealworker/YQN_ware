# GHS 静态库存与场景绑定

输入是用户提供的 2026-11-25 库位库存 CSV、GHS 0.23 原始 CAD，以及项目当前的场景、托位和模型清单。导入器不修改原始输入。本次接入静态导出，不代表实时库存接口。

## 数据与位置分别表示

- CSV 原始库存通过 `warehouse_id + location_id` 查询，保留数量、SKU、库位档案与更新时间。
- CAD 中的 `BLOCK_CODE`、`SEQ` 只提供排、档，不能当作每个托位的完整 WMS 库位码。
- 自动生成的绑定全部为 `confidence: rule_inferred`，即“按规则匹配，未现场核验”。本批次现场确认数为 **0**。真实库存数据不等于物理位置已经现场确认。
- 无唯一映射的场景目标保持未匹配，不能因查无映射判定为空位。地堆不做猜测绑定。

## 本批次规则与结果

1. 读取原始 DXF 实体句柄与 `BLOCK_CODE/SEQ`，核对项目清单的 CAD 身份、位置和模型。
2. 普通货架只接受 `GHS-Rxx-…`，且库区必须为 `450`；SR 只接受 `GHS-SR-xx-…`，且库区必须为 `454`。不合并历史编码族。
3. 第 `SEQ` 档生成三个位置号 `(SEQ - 1) × 3 + C1/C2/C3`。本批次 55 个有效排的档号沿 CAD +Y 递增，模型三列也按这个方向排列；档内现场标牌方向仍属推断。
4. 通道上层根据托盘底部实际高度，对齐同规格完整货架的物理层。A 通道上两层是 3/4；B 上六层是 7–12。不得直接使用通道模型局部层号 1/2。
5. WMS 完整码、库区、档号 `horizontal_num`、层号 `location_layer` 均一致才生成候选，双向重号全部拒绝。
6. 绑定同时保存原始场景注册清单的完整变换契约：`expectedPositionM` 为 CAD 米坐标，`expectedWorldRotationDeg` 为 UE 世界 `pitch/yaw/roll`，`expectedWorldScale` 为三轴缩放，`expectedMesh` 为完整货位 `_Capacity` 网格。旋转依据 `apply_refinement_v2.py` 的坐标转换，不能从当前已改动姿态重新认定；同一 CAD 身份的冲突变换全部拒绝。

## 更新方法

在项目根目录运行（Python 3.10+）：

```powershell
python Tools/GHSInventory/import_inventory.py --help
python Tools/GHSInventory/build_bindings.py --csv '<库存 CSV 完整路径>' --cad '<原始 DXF 完整路径>'
python Tools/GHSInventory/test_build_bindings.py
python -m unittest discover -s Tools/GHSInventory/tests
```

生成文件 `Content/GHSTwinUI/data/inventory-bindings.json` 记录源文件 SHA-256、规则、推断限制、逐托位绑定和差异数量。更新 CAD、场景或库存后应重新生成；不能复用别的仓库 ID 或丢弃源编码前缀。

三个运行时源清单 `scene-bindings.json`、`rack-slots.json`、`storage-capacity.json` 通过 `.gitattributes` 保留原始字节，避免 Git 自动转换换行后使哈希校验失败。
