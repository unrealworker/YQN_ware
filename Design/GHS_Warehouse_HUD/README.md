## 设计方向

依据当前 NormalWarehouse 的浅灰环境、银白设备、工业蓝托盘/层板及绿色设备特效设计。主体采用半透明银白信息卡、深灰蓝文字、工业蓝识别线和细锚点引线；复杂背景提供深灰蓝选中卡。

| 用途 | 色值 |
|---|---|
| 主文字 | `#24384B` |
| 次要文字 | `#64788B` |
| 工业蓝 | `#24569A` |
| 正常运行 | `#16876A` |
| 预警 | `#A66514` |
| 故障 | `#BA4140` |
| 离线 | `#788896` |

中文使用 Noto Sans SC；编号使用 IBM Plex Mono；核心数值使用 IBM Plex Sans。

以 1920 × 1080 为设计基准，常规详情卡由 456 × 268 px 收紧为 **320 × 184 px**，面积减少 51.8%。内边距由 20 降至 12 px；标题区图标改为 32 px；数值保持 28 px，单位紧邻数值。副标题保留设备编号，移除重复的英文类别；任务和连接信息各占一行。

常驻标签高度由 42 降至 **34 px**，按内容自适应宽度，取消数值前的弹性空白。六类示例宽度分别为：AGV 181、堆高车 210、充电器 196、月台 217、车辆 231、库位 200 px。状态页采用同一规则；告警和离线提示条宽度为 320 px。导出 PNG 为 2 倍尺寸，居中描边包含在边界内：详情卡 642 × 370 px，标签高度 70 px。

`exports/compact-layout-comparison.png` 展示相同比例下修改前后的详情和常驻标签。三张画板、六类详情、六类标签和全部状态变体已同步更新。

## 信息与状态

Pencil 画板中的设备状态、任务号、库位号、时间、电量、速度、功率、载荷和库存数值均为设计占位，不代表当前设备遥测。六类卡片覆盖：AGV 电量/速度、堆高车电量/货叉高度、充电器功率/剩余时间、月台托盘数/进度、车辆装载量、货架库存/层级。

紧凑标签显示编号、文字状态和一个核心指标；选中展开两项核心指标和任务摘要。状态通过颜色、文字、图标共同编码。离线显示 `--` 与最后在线时间；告警条给出具体原因与建议。

Pencil 文件包含六类设备的视觉设计与静态导出。装卸车辆和场景中 12 台电动堆高车已接入 UE 原生 UMG，紧凑布局使用 320 × 184 px 详情卡与内容自适应的 34 px 标签。堆高车标签显示编号、运行状态和电量，详情补充货叉高度、地堆区域和任务。初始演示样本覆盖运行、待机、预警、故障和离线；“演示”是独立标记，不替换实际状态文字。接入真实遥测后清除演示标记，重新发现设备也不会覆盖已接入数据。离线指标和任务清空为未知值。

聚合启用时，当前游戏视口横向和纵向各二等分，并按设备类型分别聚合：装卸车只与同格装卸车成组，堆高车只与同格堆高车成组。同格同类多台设备显示为 184 × 34 px 数量标签，单台保留独立标签；同一区域可以同时存在装卸车和堆高车两个活动标签，每类最多四个、合计最多八个，跨区和跨类型均不合并。组标签始终使用对应设备类别和图标，保留组内最高级别告警，故障优先于预警。四等分随实际视口宽高和 DPI 自适应，不显示网格线。点击数量标签后打开 260 px 宽、仅含本类设备的成员列表，每页五台；选择成员再展开详情。

四等分只决定成员归属，标签贴近本组真实成员投影中心：自然位置为 `Anchor - (标签宽度/2, 50)`，仅在整个视口边缘做限制，不再使用象限边界或固定类型分带推移标签。聚合标签首次相互遮挡时按自然上下顺序做一次局部排布，在自然位置上下 40 逻辑像素内选择所需的最小移动，同高度时装卸车优先在上。跨区或同类型标签也适用此排布，但成员不因此合并；每组额外位移不超过 40 逻辑像素，并锁定到稳定的组 key。其他标签离开或重入不改变已锁定且仍存活 key 的偏移，不逐帧累计避让。近景逐台标签保持原有跟随规则。

工程边界：设备极密且 ±40 像素范围内无可行排布时，保留当前局部位置，优先保证标签贴近设备，不扩大偏移上限。

合并/拆分改为 **120 ms**：旧标签原地淡出，新标签在目标位置就地淡入，只保留最多 **8 px** 的局部过渡，不让标签长距离飞向聚合中心。列表和详情开合保持 220 ms；跨格需持续 200 ms，窗口尺寸变化则立即重算区域。点击区域跟随动画的实际位置、缩放与尺寸。AGV、充电器、月台和库位仍为设计组件，待逐项接入。设备接入说明见 `../../docs/GHS_DockTruckHUD.md`。

## 验证

2026-10-19 新增第五张人工叉车画板，仅进行 Pencil 设计和图片导出，等待用户另行下令接入。人工叉车采用有人驾驶识别，常驻示例宽 171–193 px、高 34 px；详情 320×184 px，使用载荷/速度、驾驶员工号、区域和任务信息，不预设电池或燃油。五状态和聚合数量已逐项目视检查，完成布局边界检查并保存源文件。该画板的 120 ms 聚合和 220 ms 详情为动效规范，尚未开发动画。现有运行时两类设备的数量上限与验证结果不因此变化。

已检查四张导出画板与独立组件：字体显示正常，信息未被裁切，场景锚点落于设备，示例数据标记清晰。组件和画板图像由 Pencil 直接导出。第四张画板已同步四象限内按类型分别聚合、120 ms 局部淡入淡出和五种堆高车状态说明，展示静态关键状态，实际动画由 UE HUD 实现。本次第四张画板修改已通过 Pencil 布局检查并重新导出，`.pen` 源文件已通过 File → Save 保存。

Warehouse Camera 分类提供 `HUD 聚合最小臂长`，默认 10000 cm。当前弹簧臂低于该值时逐车显示；达到或超过该值时使用上述四等分同类型聚合。两种模式的标签均只限制在整个视口内，四等分不再限制标签摆放。切换模式保留合并/拆分动画和已选车辆详情。

当前真实锚点与连续局部排布版本已编译通过，`Saved/Automation/HUDAnchorProximity/index.json` 记录 44 项自动化通过、0 失败、0 警告；Full、Narrow、LowAngle 各通过 28 项真实运行检查，测试未保存场景资产。已检查实景标签位置与可读性，低角度截图为 `Saved/GHS_StackerHUD_SeparateTypesWide_LowAngle.png`。此前固定分带的 40 项自动化结果仅为历史记录，该位置方案因把标签推离设备而撤销。详细记录和完整报告路径见 `../../docs/GHS_DockTruckHUD.md` 与 `../../docs/GHS_StackerHUD.md`。窄屏长编号和数值省略，详情仍显示完整字段所需的信息层级。
