# GHS visual polish

Run `Scripts/ghs/apply_visual_polish.py` in the existing editor, outside PIE, with `/Game/Maps/GHS_CAD_NormalWarehouse_ZcoolSmartFactory` open. Then run `Scripts/ghs/validate_visual_polish.py` live and again in a read-only Python commandlet for saved-state verification.

UE5.4 hides the WPO enum and protects the reflected input. The narrow `GHSVisualMaterialLibrary` helper in `Source/Test` connects and checks that one input for owned VisualPolish materials; it requires the editor module to be rebuilt once. It depends only on Engine, performs no automatic save/compile, and returns false outside editor builds. `close_visual_polish_editor.py` verifies the restored scene and saves only owned work before quitting; `restore_visual_polish_editor.py` restores the recorded viewport/selection and restarts the dispatcher after reopening.

The prepared `visual_polish.json` contains the approved blue-gray campus, subdued continuous outer greenery, narrow blue campus edge, and existing-light adjustments. `T_VisualPolish_CampusMask.png` is a 2048² linear data atlas; runtime materials use at most one texture sample and no transparency, emissive, fog, Lumen, or added lights. Regenerate it with bundled Python and `Scripts/ghs/prepare_visual_polish.py` only when changing the atlas geometry or default configuration.

Seven component bindings change: the park ground, studio backdrop, hardstand, park landscape, two circulation-road surfaces, and outer context landscape. The parking surface (`GHSPark_Roads`), curbs, markings, roof and dissolve bindings, all trees, vehicles and meshes remain untouched. The landscape material keeps non-forest planting at its original tint. Only forest-pad vertices at their documented original Z values (8 and -16 cm) receive a material offset to 0.12 cm above the current ground plane. This removes the island rims without editing the mesh or moving trees. The preserved trunk bases can consequently sit about 25 cm above the continuous field; assess this at overview scale and in the forest close-up.

The only camera change is the placed camera's `overview_pitch`: -48 to -43 degrees, otherwise four degrees less negative than the original instance value. Its initial value is recorded once, making reruns stable. Blueprint and native defaults are not edited. All actor, component and instance transforms remain subject to exact preservation checks.

Each apply creates a timestamped `Saved/VisualPolish/<timestamp>/` containing the original disk map, before/after snapshots and report. It also saves a private duplicate of the live map under `VisualPolish/Backups` so unsaved manual edits are recoverable. Original materials are never modified; only owned visual-polish assets and the target map are saved. On an exception, component bindings, lighting and camera pitch are restored in memory.

Review `Saved/VisualPolish/apply_report.json`, `live_validation.json`, and `saved_validation.json`. Check the render log for material compilation errors and visually inspect a full overview plus the forest/parking junction before accepting the result. To recover, open the reported private backup map or restore its disk-map backup while the target map is closed; retain the source before/after reports.
