# 播种机环形运动逐帧平滑

针对用户圈出的单台播种机内部环形载具，修复每 50 ms 才更新一次显示位置导致的停帧与跳步。此前中央传送装置已经平滑，单台播种机仍直接显示固定步长模型位置。本次修复全部 22 台、88 个环形载具，沿用原 MPR 关卡。

## 实现

- 固定步长分拣模型和工艺速度不变，表现层按帧间剩余时间采样环形距离、升降、进料和投放进度。
- 按弧长计算直线与弯道位置和朝向，立柱、托盘、货物使用同一显示时间。
- 采样不执行业务事件、不转移包裹身份、不提前换仓；在实际需要停靠的目标口限幅，保留正常分拣停顿。
- 复用逐帧实例历史提交，避免新的平滑运动丢失前帧信息。没有修改抗锯齿、灯光或材质设置。
- 暂停保留当前显示姿态，重置清理残余时间和渲染历史。

## 验证

TestEditor 编译成功，30 项 MPR 测试全部通过，包含新增 3 项采样测试（60/120 Hz、不规则步长、1/2/4 倍速、跨环、升降、停靠、进料间距、身份守恒、暂停和重置）。

原生组件读回全部 22 台设备。仅对实际运动区间判断连续性，正常停靠、状态切换前后 75 ms 及过长测量帧单独排除并记录。

| 验证条件 | 修复前重复位置次数 | 修复后重复位置次数 | 修复后有效载具帧数 |
| --- | ---: | ---: | ---: |
| 60 Hz 指定步长 | 8152 | 0 | 12260 |
| 120 Hz 指定步长 | 10040 | 0 | 12056 |
| 不规则指定步长 | 7660 | 0 | 12576 |
| 原生 Tick，60 FPS 上限 | 6684 | 0 | 12476 |
| 原生 Tick，120 FPS 上限 | 6668 | 0 | 11880 |

修复后五组测量的超限跳步均为 0，每组包含至少 2400 个弯道载具帧。原生 Tick 实际测量频率约 60.00/119.72 Hz。基线使用旧版完整诊断报告，读取开销使该采样约为 43 Hz，因此前后实际 Tick 次数不作严格同帧比较；指定步长的前三组完全一致。

独立性能采样不读组件、不截图：1920×1080、60 FPS 上限、TSR，900 帧约 15 秒，平均 60.00 FPS、P95 帧时间 16.67 ms、最大帧时间 16.79 ms。此为本地原生进程样本，不代表串流性能。

`ring_cad64.png` 和 `ring_cad120.png` 为两类播种机固定镜头截图；运动连续性以原生逐帧位移测量为依据。原场景、资产与相机保留结果见 `scene_preservation.json`。

复现入口：`Tools/MPRWarehouse/verify_mpr_ring_motion.py`，在原 MPR 关卡独立进程运行，参数包含 `-game -RenderOffscreen -TwinDiagnostics -EnablePython -ForceRes -ResX=1920 -ResY=1080`；`-MPRRingBaseline` 可记录旧版缺陷而不要求平滑断言通过。
