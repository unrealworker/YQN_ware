## 本场景的实现取舍

以下为代理方案，用于用户要求的工作状态演示，并非厂家调试规范：

1. 只纳入现有 18 台 `cad64` 和 4 台 `cad120` 长机，保持摆位、格口外壳和料框；这 22 台使用同族机理展示。场景现有 4 层是模型展示配置，不能因此宣称型号/产能已由原 CAD 证实。30 台 `Short10` 不在已证对象范围，保持原状；独立 96 格资料模型不放入关卡。
2. 去除长机内部原来用于占位的多层长皮带和实心端柜，加入开放导轨、移动立柱与独立升降托盘。运动尺寸从保留的场景几何标定，水平轨道是拟合展示路径。
3. 每机 4 个载具共享链相位，间隔为环路的 1/4，不能互相超越。载具沿环路移动时托盘可独立升降；扫描、等待升降、卸料或满格时可停共同主链。这是可解释的演示控制策略。
4. 循环为：端部接货/扫码 → 分配演示目标 → 环行与升降 → 对准列/层 → 短带侧送、沿固定槽入箱 → 目标箱计数 → 空载返回。只在卸料完成时累计一次。
5. 使用可重复的演示目标队列及唯一包裹 ID。没有真实订单、SKU 分配、波次履约、WMS、WCS 或 PLC 联机。面板明确显示“演示数据 · 全部设备同步控制”。
6. 演示包裹尺寸为 22 × 16 × 5 cm，每格容量 3 件、模拟取箱间隔 12 秒；这些是场景展示参数。首次入箱后开始计时，重新开启自动取箱时重计完整间隔。若格口仍有卸料预留 `Reserved>0`，手动取箱被拒绝，已经到期的自动取箱等待卸料结束；堆叠位置在整个投料过程中保持稳定。可关闭自动取箱，也可人工清空满格。取走数量单独累计，清箱不会伪造消失的货物。
7. UI 提供开始/暂停、复位、1×/2×/4×、定位设备、模拟取箱开关和清满格。仿真控制作用于全部 22 台，设备切换、定位和统计显示针对选中设备。保持现有关卡、GHS 相机和点击屋顶溶解功能。

初版研究曾讨论“一演示订单绑定一箱”的可选业务表达；当前实现仅采用目标队列，不实现或声称该订单模型。可确认的是物品向目标格口归集，具体订单映射仍需真实业务接口定义。

## 验证约束

- 包裹标识以设备及复位周期限定；活动 ID 不重复，同一包裹只计入一个格口。
- `格内数量 + 预留数量 ≤ 容量`；满格时等待，不穿箱或丢件。
- `生成数 = 完成入箱数 + 运行中数`；`完成入箱数 = 格内现存数 + 已取走数`。
- 暂停冻结主链、升降、卸料、扫码和取箱计时；复位清空演示状态、恢复暂停和 1×。
- 大步长与 4× 时间推进逐事件处理；被拒绝的非法时间步不产生局部状态更新。
- 保留格口/料框，检查真实商品路径和机构间隙；前后固定机位截图、运行帧率和独立重载验证与纯逻辑测试分别保留。
