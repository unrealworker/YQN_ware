# MPR 供包输送线与地面占位修复

修复范围为现有关卡的 111 个实例：3 台供包爬坡，108 个被错误建成带显示器桌子的 CAD 叉格。保持原 CAD 平面位置，不增加连线、不移动播种机、不修改 GHS 共享资产。

## 源图根因

- `2CCF62`、`2CCF66` 为“供包爬坡”；`2E7F10` 为“供包爬坡机”。原实现直接按块包围盒缩放 GHS 通用滚筒，其输送轴是局部 Y，而 `2E7F10` 的 CAD 输送长轴是局部 X，造成短宽滚筒台和错误输送方向。
- 专用网格采用源 CAD 皮带边缘。`2E7F10` 的 `2E7CE9` 给出约 2.42179 × 0.8 m 的有效皮带面；另外两台通过 `1E2EE4`、`1E2F21` 等给出 0.586 m 内带宽。护板与支腿采用简化结构。
- `A$Cb1177cf1` 实际仅含一个矩形和两条对角线，没有桌面、桌腿、显示器或输送结构。108 处均恢复为轻量地面叉格。矩形用途尚不能单靠该符号认定为工作台、托盘或货仓。
- 原图供包台与中央设备本来留有间隔，未画出连续传送接驳。此修复没有按最近距离补带。人员交接、速度、传感器和运行方向仍需工作流单独明确。

## 重要边界

CAD 是平面图。新增皮带的 0.74 m 至 1.0 m 高程是展示假设，不能当作设备施工高程。`321321` 容器框和中央 650 mm 地网均不属于已证明的输送线。矮排组件中主机与可更换空仓应依据另外的组件审计区分。

## 应用契约

`patch_manifest.json` 每项包含原 Actor GUID、组件名、HISM 索引、网格路径及完整预期变换。应用前必须全部匹配；同组件按索引降序删除，仅替换目标实例。新实例的 CAD Y 与旋转由现有 FBX/UE 管线仅转换一次。三台供包网格已按 CAD 全局 XY 相对中心制作，实例旋转为 0；地面叉格保持原实例旋转、缩放。

目标资产目录：`/Game/MPRWarehouse/ConveyorAudit20261107`。材料角色在 `MPR_CADConveyorAudit.json`，复用既有角色材质但不能修改共享材质参数。关卡、镜头、光照、屋顶、其他输送段及播种机均由局部补丁保护。

## 重现与验证

1. 普通 Python 运行 `Tools/MPRWarehouse/full_conveyor_cad_evidence.py`，只读原 CAD 并生成可追溯几何证据。
2. Blender 后台运行 `Tools/MPRWarehouse/full_conveyor_build_patch.py`，生成本目录 4 个 FBX、源 blend 和精确补丁。
3. 运行 `Tools/MPRWarehouse/full_conveyor_verify.py`。
4. 可用 `build_mpr_operations.py --output <项目内绝对隔离目录>` 验证未来全量重生不会恢复旧错误；不需覆盖正式 operations 或关卡。

本次独立回归覆盖 886 个操作区实例：只改变指定 111 个，其余 775 个逐字段完全一致。最终护板修订后补丁总计 744 三角面。两台 `2CCF62/2CCF66` 的侧护板与内框连续相接，下方横梁连接支腿，避免近景仍被看作悬空栏杆；原皮带边界、外轮廓和实例位置不变。完整初始审计与原 CAD 对照图保存在 `Saved/MPR/full_workflow_20261107/conveyor_audit.json`、`conveyor_audit.md`、`cad_context_user_region.png`。这不代表所有工艺方向与高程已被 CAD 证明。

原生 UE 验证归档在 `validation/`：4 组同镜头、同曝光、1920×1080 前后截图，保存后独立重载通过；877 个无关 Actor 与 1910 个既有 Content 文件保持不变（仅目标关卡除外）。最终护板再次导入后关卡文件未变化，截图重新验收。
