# GHS 订单追溯 · 交互与场景回放方案

日期：2026-10-23 · 状态：待确认的独立设计方案

本轮交付为可交互设计原型和本说明。没有替换现有 `Saas.pen`，没有修改 UE、业务网页或场景资源。原型中的车辆运动为作业示意，不代表 UE 取货动画、路线碰撞和性能已开发验证。批准方案后，再更新正式设计稿并实施。

## 1. 核心体验

**选择至少 1 小时 → 索引订单 → 选择订单进入 → 回看该时段全部设备 → 跟随、暂停、定位关键事件 → 结束并恢复现场。**

订单用于进入追溯，不用于过滤设备。页面持续显示“全时段设备回放”，避免误以为只回放一笔订单的轨迹。

界面的首要问题是：这段时间，货物如何从地堆运到装卸车，哪里发生了异常？场景是主体，右侧提供设备和事件，底部提供时间控制。不要再用一排统计卡片抢占场景。

本次没有真实轨迹和订单数据。所有测试订单、设备任务和事件均为预制，不能表示真实业务事实。

## 3. 页面状态

### A. 选择时间

右侧标题“订单追溯”，下面依次放开始时间、结束时间、快捷时长和主按钮“索引订单”。

- 时间统一使用仓库当地时区 `America/Los_Angeles`，在日期区显示该区间的 UTC 偏移。顶部实时钟不能替代回放时间。
- 默认区间为 1 小时，提供 1 / 2 / 4 小时快捷长度。时间长度按真实经过秒数计算，最少 3600 秒。
- 小于 1 小时、结束不晚于开始、无效日期：在对应输入下方解释，保留用户输入，不进入查询，不切换场景。
- 测试模式允许任意有效日期区间，始终索引出相同的 4 个测试订单。未来正式数据模式再依据数据可用范围提示。
- 跨夏令时的真实实现：不存在的当地时间拒绝并说明；重复出现的时间须选择 PDT / PST 偏移，不能静默猜测。跨偏移区间起止分别标明偏移。

### C. 回放中

进入时先准备回放层，准备成功后隐藏原设备、展开屋顶，再从区间开始播放。失败则回到订单列表并完整恢复进入前场景，不留下半清场状态。

右侧面板结构：

1. “订单追溯”与“结束追溯”。
2. 当前入口订单、测试回放标记、起止时间、全时段设备回放说明。
3. “设备 8 / 关键事件”页签。
4. 设备列表：5 台人工叉车与 3 台装卸卡车。每项显示编号、当前动作、载货状态，支持选择和跟随。
5. 事件列表：时间、设备、动作摘要；故障用红色，恢复与作业完成用蓝色。点击定位到时间点并暂停。

设备列表的数量是本轮参与回放的设备数；某卡车离场时仍保留行并标“已离场”，不能因为场外无模型就把参与数改成 7。

### D. 暂停、结束、完成

- 暂停：场景动作、货物归属、道路车辆、轨迹流动与回放时间一起冻结。
- 到达结束时刻：停在精确终点，显示“回放完成”，提供“从头回放”和“结束追溯”。不自动重播整段时间。
- 手动结束：确认后恢复原场景，回到当前时间段的订单列表，方便换订单。
- 完成后仍处于回放场景；切换其他业务页面时也需要结束确认。

## 4. 时间轴与相机

| 控件 | 交互 |
| --- | --- |
| 播放 / 暂停 | 控制统一回放时钟；暂停不会丢失跟随目标 |
| 后退 / 前进 30 秒 | 定位到目标时刻，限制在区间内；保持原播放或暂停状态 |
| 倍率 | 1×、2×、4×、8×、16×、32×、64×，默认 1×；高倍率仍可暂停和定位 |
| 时间滑块 | 按下暂停，拖动预览时间，松手重建该时刻状态；原来播放则继续，原来暂停则保持暂停 |
| 事件标记 | 蓝色作业完成、橙色等待、红色故障；通过形状和提示补充颜色，悬停显示时间与摘要 |
| 事件点击 | 定位并暂停；高亮相关设备，不擅自改变相机跟随目标 |
| 跟随设备 | 平滑移动到设备后上方；保持稳定观察距离，低速跟随转向，不做突兀镜头翻转 |
| 取消跟随 | 留在当前相机位置进入自由观察；另提供“回放全景”回到回放概览 |
| 手动旋转 / 平移 | 退出跟随，保留设备选择，提示“已切换为自由视角” |
| 轨迹显示 | 全部 / 仅选中 / 关闭，默认全部；只影响轨迹，不过滤设备 |

时间轴上方显示完整回放日期、当前时分秒、已播放 / 总时长；两端标识起止时间。跨天时刻标签必须带日期。真实当地时钟和回放时间使用不同标签。

同一区间相同时间点的设备位置、载货状态、故障状态必须可重复。后退后应重新看到尚未卸货的托盘；快进不能只移动模型而遗漏货物转移。

长区间的事件按可见时间范围获取/生成、列表虚拟滚动，时间轴近邻标记合并并显示数量。选中聚合标记打开该时间段事件列表，不让标记重叠到无法点击。高倍率下压缩提示频率，但不丢失事件记录。

建议以约 12 分钟的出库作业波次错峰展示，再接固定的补给波次，组成可循环的完整测试周期。原型用简化周期讲解取货和装车；正式场景每段时长按实际路线长度及车辆速度重算，不强行把整轮压缩为 12 分钟。每台叉车完整动作必须连续，不在周期边界瞬移回起点。每轮事件使用独立事件 ID，绝对时间从区间起点推导，区间终点截断当前动作。

装载容量在资产尺寸核对后定稿；建议 A / B / C 分别为 4 / 2 / 4 托作为演示装载目标，对应 5 个取货点各 2 层、合计 10 托。不把演示目标当作真实额定容量。容量由实际卸下的托盘数累计，不能按独立计时器无货装满。离场后的后续车辆是下一车次，上一车次与下一车次的货物替换只发生在场外。

为同时保证任意时段连续作业、不凭空生货和任意 seek 可重复，补货不依赖镜头：满车离场后，下一辆测试补给车按固定时刻沿入口驶来，携带对应数量货物；原叉车将补货按反向作业流程送回来源点，再开始下一轮出库。补给车卸空后成为该装卸位的下一辆待装车。回流补货明确标“测试补给”，不冒充真实业务；三个泊位波次错开，其他叉车可同时出库。所有补给、等待与放行时间均由固定任务表决定。

### 货叉与托盘动作

1. 地堆保持现有两层蓝色底托盘；仅回放取货点使用可拆分副本。
2. 叉车沿通道减速、摆正，停稳后升降货叉对准目标托盘插孔。
3. 插叉、轻抬，**先取上层“一个蓝托盘＋货物”**，下层仍在地面。
4. 倒车离开货堆，降到运输高度；货物固定在叉架载货挂点上随车运动。
5. 到装卸位停稳、升到车厢入口高度，前进放货、落叉、退叉。
6. 托盘归属由货叉转到车厢；叉上载货消失，车内新增同一托货，不能同时出现两个。
7. 下一趟可搬同组下层；待此来源点两层搬完，按固定任务表等待或参与补给。测试补给车到场后，叉车先将下层放回地面，再将上层落在下层上，以可见搬运动作恢复两层蓝托盘；不在用户眼前凭空长货，也不因镜头变化决定是否补货。

装卸过程中卡车保持驻车、尾门打开。叉车退出车厢并离开尾门安全区后才允许关门、起步。卡车离场沿园区已有门口连接当地道路，不直接横穿边界进入 I-15。

## 6. 蓝色轨迹效果

- 使用贴地带状曲线，起点、终点有小型节点；主要路径宽约 0.45–0.7m，最终根据真实车道比例调整。
- 全部轨迹低透明度，选中设备轨迹略加深；其余轨迹保留但减弱。方向由短段流动表达，不堆叠长箭头或科技网格。
- 轨迹绘制合法已安排路线；转弯为连续曲线，转弯速度降低。载货与空载可以用实线和短虚线区分，仍沿用同一蓝色。
- 暂停时流动停住；倒退和跳时间时流动相位随回放时钟更新。故障不把整个场景染红，只保留设备故障点。
- 轨迹略高于地面避免闪烁，但不能盖住车轮和托盘；穿过屋内门口仍贴合真实地面高度。

## 7. 场景隔离、退出与恢复

进入回放前保存：相机位置/朝向、屋顶状态、图层开关、选中对象、原设备显隐、常规交通显隐与运行状态。回放使用独立注册表与唯一前缀；拾取、标签、跟随只访问回放设备。

清场范围包含原人工叉车、AGV、装卸车、停车场小车、园区展示车辆及主干道常规车流。固定建筑、货架、地堆、道路与绿化保持。固定充电设施按原图层保留，但不显示常规设备 POI。进入前手动隐藏的对象，结束后不能擅自显示。

原设备只隐藏并暂停，不删除，不改变用户手动摆放。回放结束清理回放车辆/货物/路线及回放标签，再恢复快照。回放搬运不修改业务库存、设备台账、永久地堆数量或图层配置。

### 退出确认

标题：**停止追溯并前往总览？**（目的地随原操作变化）

正文：**当前回放将结束，场景恢复到进入追溯前的状态。**

按钮：`继续追溯` / 蓝色 `停止并前往总览`。手动结束时文案改为“结束追溯？”与“结束并恢复场景”。

- 提示出现时暂停，记录原来是在播放还是暂停。
- 取消、Esc 或关闭提示：保留时间、倍率、跟随目标，恢复提示前的播放/暂停状态。
- 确认：先结束和恢复，再执行原点击操作一次。不要只回首页，也不能重复执行定位。
- 恢复过程中锁住重复提交；恢复失败不继续导航，说明错误并允许重试，不遗留隐藏场景。
- 导航栏、返回、全局搜索结果、设备定位、常规预设视角、Home 键、中键全景复位及原生业务跳转均经过同一守卫。
- 回放内部切页签、跟随/取消、缩放、自由观察、轨迹开关、回放全景和面板收起不视为离开，不弹确认。
- 回放中修改时间/入口订单先结束确认，确认后回到保留输入的索引页再选择，不静默替换正在看的场景。

原型的其他业务页面只演示“确认后抵达原目标”的状态，不复制整个原产品功能。实际集成须保存原导航或定位参数，而不是只保存页面名。

| 现有相机支持 `FocusOnTarget/TransitionToPose` | 可复用镜头过渡；持续平滑跟随仍需开发 |

**不穿模必须在当前地图验证。** 许多静态实例没有碰撞，不能只依赖物理碰撞查询。需导出墙柱、货架、地堆、门洞和地面几何，以车身＋货叉＋托盘的完整包络检查直线、曲线外摆、上下坡、门高、车厢入口、倒车和卸货全过程；交叉口使用时段预约/让行，验证车辆相遇不会互穿。预览图不作为这项验收证据。

## 9. 数据与性能原则

未来测试数据与真实数据共用回放状态协议：区间起止 UTC 时间、当地时区、订单引用、设备身份、轨迹、动作、货物归属、事件。模拟数据必须带 `isTest: true`。一个入口订单可以关联查询结果，但不能把全时段设备集截断为一单。

| 数据对象 | 最少字段 |
| --- | --- |
| 回放区间 | startUtc、endUtc、timeZone、isTest、datasetVersion |
| 订单索引 | orderId、isTest、区间内关联时间；测试单固定身份 |
| 设备状态 | replayDeviceId、type、时间、位置/朝向、速度、动作、故障、车次 |
| 货物状态 | cargoId、来源堆/层、当前归属（地面/货叉/车厢）、目标装卸位 |
| 关键事件 | eventId、timeUtc、deviceId、type、说明、可选 orderId/cargoId |

单一时钟驱动车辆、货叉、载货、故障、事件和轨迹材质。通过时间直接求值或从近邻检查点恢复；快进不能逐帧补跑全部历史。测试数据按周期和可见窗口惰性生成，不能为任意长时段预先建立百万条事件。

5 台叉车、3 个卡车槽及有限货物池复用，驶出视野再回收。线路预计算，材质只更新回放时间。列表与文本采用降频刷新，轨迹不每帧重建网格，不反复刷新整个库存实例数组。对象数、事件节点数、内存均随场景规模有界，而非随播放时长持续增长。

每人独立会话必须拥有自己的回放时钟、相机、隔离快照、车辆与数据状态，不影响其他访问者。后续性能评估遵循已确定的“每人独立”标准，默认 1920×1080、60 FPS、超清；本轮没有运行此项性能测试，不能据原型宣称达到帧率目标。

## 10. 批准后的验收清单

1. 59 分钟 59 秒不可索引，恰好 1 小时可索引；跨日、跨夏令时的区间计算正确。
2. 任意合法测试时间段返回相同 4 单；选择任一单在同一相对时刻得到相同 5 叉车、3 卡车及路径状态。
3. 屋顶打开且原车和原标签被隐藏，只能选回放设备；结束后精确恢复进入前设置和用户手动摆放。
4. 5 台叉车至少分别执行一套完整取货—载货—卸货—返回动作；双蓝托盘逐层减少，货物归属唯一。
5. 至少一辆卡车装满关门、沿出口上当地道路、出边界回收；其他叉车可持续往返直到终点。
6. 全部路线在当前保存地图上通过完整包络、动态交叉、门洞和车厢验证，不穿墙、不穿货堆、不穿车。
7. 暂停冻结全部状态；任意跳时间、故障前后拖动、倍率切换、后退能得到一致状态和正确事件。
8. 时间轴标记与实际动作在同一时刻出现；故障停 45 秒后恢复，不能只改变状态文字。
9. 跟随稳定，无镜头跳变；取消保留当前自由视角，回放全景可复位。
10. 退出确认取消保留原进度，确认恢复后准确执行原操作；覆盖页面跳转、搜索定位、Home、中键和原生入口。
11. 区间末尾停住并显示完成；重新播放仅由用户触发；长区间资源数量不持续增长。
12. 每人独立、1080p/60/超清下测帧时、卡顿峰值与内存；以真实 UE 记录验收，不能用网页预览帧率代替。
