## 本机远程访问边界

本机可以打开固定 HTTPS 网页并建立信令，本轮未收到视频媒体，媒体接收为 0 字节，因此不能宣称“本机远程像素流已验收通过”。追加定点测试确认，本机到服务器被测 UDP 地址和端口的路径未通。

网页和信令通过 HTTPS 链路传输，视频另经 WebRTC 媒体链路传输。**能打开这个链接，不等于视频所需的服务器候选地址与 UDP 端口已经可达。** 服务器自身 Edge 的成功证明包与服务器内媒体路径可运行，不能代替用户电脑所在网络的验证。

### 追加网络诊断

| 测试 | 结果与含义 |

| 私网 TCP 旁证 | 直连 `http://10.100.185.161:8080/health`，TCP 等待 4 秒超时；此项不是 UDP 端口测试 |
| 独立 UDP 定点测试 | 服务端绑定 `10.100.185.161:50199` 45 秒，仅回显预设随机标识，随后自动释放；本机 `172.16.11.175:64355` 连续 4 次发送均超时，服务端 `received=0`、`echoed=0` |
| 生产媒体监听 | UE PID 16972 监听 UDP 50001、PID 18112 监听 UDP 50000；二者均在 `10.100.185.161` 与 `10.8.0.32` 接口存在监听 |

独立 UDP 测试在服务端已绑定、客户端已发送的情况下仍未收到任何数据，因此本轮已确认被测客户端到服务器 UDP 路径不通；不能仅归因于 PixelStreaming2 未启动。该结果尚不能精确定位阻断位于客户端路由、VPN、网关、安全组、ACL 或主机防火墙的哪一层，也不能简化为“只是 VPN 没开”。应以实际 ICE 候选地址和端口继续逐段核对，而不是把域名 HTTPS 200 当作媒体连通证据。

末次浏览器采样 `local-final-ice-proof.json` 中，两条连接已关闭且无候选；另一条为 `failed/disconnected`，记录 5 条候选但没有候选对。该采样没有完整的 ICE 检查过程，不能用它声称已完成 UDP 协商或定位其失败阶段；上述 UDP 不通结论依据独立定点测试的服务端零接收结果。

新旧 12 项入口、网络和访问配置对照一致，均配置 STUN，均未配置 TURN。下一步应修通客户端到媒体候选地址的 UDP 路径；无法直连时配置可达的 TURN 中继，再用本机浏览器验证首帧、持续播放与交互。当前没有证据要求仅为本轮无画面而升级 NVIDIA 驱动。
