# 像素流流畅度与资源优化实施计划

**目标：** 保持现有仓库视觉和独立操作，取消固定 FPS 上限，减少视频缓冲与无效场景开销，改善波动网络和多实例启动体验。

**依据：** 用户已授权本轮优化现有方案及像素流源码。单人首页实测 UE 30/30 FPS，接收约 28 FPS，平均缓冲 393–427ms；库存 13 组静态 HISM 每帧强制阴影失效。先修已定位的问题，分别验证后再组合部署，不用提高任意数值冒充不限帧。

**技术栈：** UE 5.4.4 / MSVC 14.38；项目级 PixelStreaming 插件；Node 服务；官方 UE5.4 前端 1.1.6；WinForms 启动器。

## 实施与验收

- [x] 场景：库存静止采用 Auto 阴影缓存；库容拖动仅在进入和退出变化状态时重建，变化期间正确更新阴影。测试重复值、连续拖动、追溯取放、退出恢复。保持地图与资产不变。
- [x] UE 串流：在项目插件中支持全局 FPS=0，省略 RTP 固定上限、保持随渲染采集、避免除零与遗留降帧限制；正值仍支持原有行为。低延迟发送可单独开关，以便 A/B。安装引擎保持不变。
- [x] 服务与启动器：FPS=0 显示“无固定上限”，预算不按人数预先均分；默认码率 1/8/24Mbps，保留旧配置和自定义预算；同一时间只启动一个新 UE 实例，已运行连接不受排队影响。
- [x] 浏览器：适配官方 SDK 的零帧率语义；接收器按支持程度请求低延迟；记录实际缓冲、重传、冻结和选中的媒体路径。修复 SDK 固定 10/100Mbps 提示，使新连接按会话协商 1/8/24Mbps。
- [x] 工程验证：86 项 Node、46 项启动器、9 项 UE D3D12 自动化通过；Editor 与 Shipping 构建成功；地图哈希保持一致。更新器通过基线、原子替换、回滚及配置保留验证。
- [x] 部署与观测：服务器在无在线用户时备份并更新；实际域名已取得 1080p 视频。保留用户录像、24/8/4Mbps 单实例完整测量及服务器资源截图，包含掉帧与冻结异常。
- [x] 交付：已分别创建中文功能提交，更新独立发行包及服务器可回退版本；详见[优化验收报告](../reports/2026-10-28-pixel-streaming-optimization.md)。
- [ ] 外部链路稳定性验收：单实例仍有突发丢包、完整帧到达减少和冻结；云出口额度、QoS 及具体异常网络节点尚未核实。不能以短时平均 FPS 或低缓冲代替流畅性结论。
- [ ] 多人容量验收：尚未完成 10 个独立实例的持续并发验证；10 人仅为接入名额，不作为硬件容量承诺。

## 网络和安全边界

保留所有可达 ICE 候选及 UDP 优先协商，不强制删公网候选以免 VPN 外用户断流。先测内网路径是否可达，存在可验证的路由收益才切换。保持 HTTPS、访问码、限流和控制接口边界，不为性能关闭认证。默认 10 人接入上限保留，它与 FPS 上限无关。

## 重点回归

1. FPS=0 不得被 SDK 夹为 1，也不得被预算恢复为 30/60/120。
2. 慢启动、断连或启动失败不能堵塞队列或造成两个初始化进程同时运行。
3. 网页隐藏/恢复、重连、SSRC 变化时指标不能使用失效计数。
4. 不支持接收延迟 API 的浏览器仍可正常播放。
5. 库容连续拖动不能每帧销毁重建所有库存组件，也不能遗留错误阴影。
