# GHS 当前场景帧率与点击瓶颈实测

日期：2026-10-28。结论：当前代表性操作路径主要受 GPU 渲染限制，优先处理阴影、TSR 抗锯齿和货架近景的几何/材质绘制。此次完成定位和诊断工具修复，**没有永久降低项目画质或修改地图**。

## 条件与基线

实测是当前本机 i9-14900HX、RTX 5060 Laptop 8GB、32GB 内存，驱动 582.05，UE 5.4.4 Development / DX12；不是此前讨论的 A40 服务器。使用当前磁盘地图、1080p、100% 渲染比例、关闭 VSync/帧率上限。原用户 Editor 保留并最小化，Figma 为静态前台；没有 Pixel Streaming 编码/网络负载。

为保留未保存编辑器工作，在 `Saved/Performance20261028/IsolatedProject` 编译相同生产源码的隔离诊断副本，通过 Content 目录联接读取同一场景。正式 7 轮使用同一诊断 DLL SHA `1c2f656ff5acc0df8db08cb6a02b2d9a457741bde4a2c9d190f4fffd13226688`。地图 SHA 始终为 `1a28e3301d524bbb9aa0a32556e684d1468d4c7f095544e8a3430599e5a5aa01`。

每轮预热 30 秒、采样 90 秒。固定路线重复两次，覆盖总览旋转、AGV/叉车定位、货架近景、真实货物点击、面板收起/展开、各业务页切换。每轮 38 个动作、2 次真实投影点击均成功选中 MATERIAL，临时状态恢复成功。

| 三轮正式基线统计 | 各轮统计量的中位数 | 三轮均值范围 |
| --- | ---: | ---: |
| 帧耗时均值 | 16.49 ms，约 60.63 FPS | 16.14–16.50 ms |
| 帧耗时 P95 | 23.90 ms | — |
| 帧耗时 P99 | 33.42 ms | — |
| GPUTime 均值 | 16.59 ms | 16.25–16.60 ms |
| 游戏线程均值 | 2.10 ms | 2.09–2.19 ms |
| 渲染线程均值 | 16.20 ms | 15.83–16.20 ms |

约 40.5% 的帧超出 60 FPS 的 16.67 ms 预算，每轮有 52–58 帧超过 33.33 ms。不能用平均约 61 FPS 宣称稳定 60 FPS。渲染线程计时含 GPU 等待，不能据此把渲染线程和 GPU 成本相加。

## 前三项 GPU 成本

下表将互不重复的相关 GPU pass 归为三组，使用正式三轮的每组均值中位数。百分比以 GPU/Total 均值约 15.99 ms 为分母，表示测得的 GPU 时间占比，不是能直接节省的 FPS。

| 排名 | 成本来源 | 平均 GPU 时间 | 占 GPU 记录时间 | 三轮范围 |
| --- | --- | ---: | ---: | ---: |
| 1 | 阴影生成与投影：ShadowDepths + ShadowProjection | **4.56 ms/帧** | **28.5%** | 4.55–4.63 ms |
| 2 | TSR 时域超分辨率抗锯齿 | **3.31 ms/帧** | **20.7%** | 3.30–3.33 ms |
| 3 | 场景几何与材质：Basepass + Prepass | **3.07 ms/帧** | **19.2%** | 3.04–3.27 ms |

1. **阴影是首要目标。** 13 组库容 HISM 共 9,159 个实例，默认均为 `ShadowCacheInvalidationBehavior::Always`，每帧强制使相关阴影缓存失效。仅 ShadowDepths 的 P95 就达约 7.72 ms。将这些组件临时改为 Auto 后，该 pass 从约 3.38 降至 2.69 ms；仍保留其他场景阴影。
2. **当前 1080p、100% 比例仍使用 TSR。** TSR pass 单独约 3.31 ms。可考虑提供清晰度/性能档位，并对 TAA 的细线、文字边缘、移动拖影做视觉验证；不能仅凭一次计时把全项目默认改成 TAA。
3. **货架近景的主通道与深度预通道增加明显。** Basepass 约 1.90 ms、Prepass 约 1.17 ms；两者各自 P95 约 6.51/4.90 ms。最后一轮货架阶段平均帧耗时约 23.98 ms，而总览阶段约 16.25 ms。这个阶段差额包含可见对象、屋顶状态与镜头变化，不能全归因给某一个模型。下一步应核查货架/货物的 LOD、遮挡、Masked 材质和过绘制，不以删除外观细节为默认方案。

## 单轮诊断对照

每种干预都是相同操作路线的独立 90 秒实验，只修改独立进程内状态。以下与三轮基线中位数比较；变体目前各一轮，属于定位证据，尚不是经过多轮及画质验收的正式优化收益。

| 临时干预 | 帧均值 | 比基线减少 | GPUTime 均值 | 边界 |
| --- | ---: | ---: | ---: | --- |
| 13 组库容阴影缓存 Always → Auto | 15.40 ms | 1.09 ms / 6.6% | 15.52 ms | 正式采用前要验证滑块改库容时的阴影失效刷新 |
| 仅关闭这 13 组投影 | 13.86 ms | 2.63 ms / 15.9% | 14.02 ms | 会改变货物落地感，仅用于隔离成本 |
| TSR → 普通 TAA | 13.39 ms | 3.11 ms / 18.8% | 12.56 ms | 改变画质，不与等画质优化混称 |

Auto 对照虽改善均值，本轮帧 P95 为 24.39 ms，略高于基线中位数 23.90 ms；ShadowDepths P95 为 11.77 ms，也没有改善尾部峰值。因此目前不能宣称卡顿已修复。

这些差额不能相加预测最终 FPS，也没有同时应用到正式场景。交通变体工具已准备但本轮未执行，因此不对交通车辆给出收益结论。

## 点击与界面调用链

独立 TraceNative01 使用同一 DLL，完整生成 351,851,301 字节 `.utrace`，经 Unreal Insights 官方离线导出。分析按 38 个动作与原生时钟对齐到 90 秒窗口，偏差跨度仅 0.0069 ms，排除开始采集前的 trace 历史缓存。

| 调用 | 实测 |
| --- | ---: |
| 真实货物 PickRay 两次 | **1.38 ms / 1.88 ms** |
| 全部 38 个基准操作，包括页面切换 | 最大 **2.85 ms** |
| HUD Tick | 平均 0.097 ms，P95 0.422 ms，最大 3.36 ms |
| HUD Paint | 平均 0.051 ms，最大 0.476 ms |
| 场景维护/刷新 scope | 平均 0.015 ms，最大 2.96 ms |
| 推送页面快照 | 平均 0.254 ms，最大 2.00 ms |

这两次点击的射线扫描仍有优化空间，但不能解释整段持续低帧率。当前测到的原生 HUD 也不是 GPU 成本前三名。没有测量 CEF 子进程内部 JavaScript、鼠标输入到显示的完整延迟及网络延迟，因此不声称所有点击场景都不卡，也不声称 React/ECharts 完全无成本。

优先顺序：先做可正确失效的货物阴影缓存，再做抗锯齿质量档位，再检查货架近景的 LOD/Masked/深度绘制；随后为 PickRay 增加空间索引。每一项都应单独验证画面、库容变更、追溯和取放货，并以同路径复测验收。
