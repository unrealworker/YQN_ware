# 追溯真实数据对接说明

日期：2026-11-09。用途：给数据提供方确认字段、导出真实样本。本次只新增说明和样例，没有修改追溯功能。

**建议先提供一小时的真实数据：订单 + 设备历史位置 + 作业任务 + 托盘取放记录 + 关键事件 + 查询起点状态。** 只提供订单数量、设备当前位置或“完成取货”文字，无法还原历史路线、车头转向和托盘搬运过程。

## 文件怎么用

| 文件 | 用途 |
|---|---|
| [orders.sample.jsonc](orders.sample.jsonc) | 查询时间段内订单列表，字段有中文注释 |
| [replay.sample.jsonc](replay.sample.jsonc) | 设备轨迹、托盘归属、任务和事件的中文注释样例 |
| [orders.sample.json](orders.sample.json) | 订单样例的标准 JSON，无注释，可被 JSON 工具直接读取 |
| [replay.sample.json](replay.sample.json) | 回放样例的标准 JSON，无注释，可被 JSON 工具直接读取 |

JSONC 便于人阅读，不是标准 JSON。真实接口或导出文件使用 UTF-8 标准 JSON。可以先交文件，不必先建设 API；已有数据库表或 CSV 也可以提供，只需保留同样的关联字段和单位说明。

**这是一份建议对接格式，当前程序尚未实现该格式的解析。不能直接覆盖 `Content/GHSTwinUI/data/order-replay.json`。** 当前是固定演示模型，后续接入时要新增数据适配、真实订单查询和非循环历史播放。这些改动应等真实样本和字段确认后再做。

样例缩小为 2 台人工叉车、1 台卡车、1 个托盘，覆盖待命、取货、载货、故障及恢复、放货、关门、离场。扩展到 5 台叉车或更多设备时，增加对应主数据、轨迹、任务和事件；不需要复制同一段演示路线。样例只用于确认格式，所有坐标和事件都是构造数据，尚未做场景碰撞校验。

## 一、需要提供什么

| 数据 | 最少字段 | 是否必须 | 缺失时的影响 |
|---|---|---|---|
| 查询范围 | 仓库编码、开始/结束时间、时区 | 必须 | 无法确定该播放哪段历史 |
| 订单索引 | 订单号、类型、实际开始/结束时间、参与设备/任务 | 必须 | 无法按时间索引和选择真实订单 |
| 设备主数据 | 唯一 ID、名称、设备类型、定位点定义、车型编码 | 必须 | 无法稳定关联 POI、轨迹和模型 |
| 历史定位 | 设备 ID、采集时间、位置 XYZ、坐标系及单位、数据质量 | 真实轨迹必须 | 只能展示业务流程示意，不能声称还原真实路线 |
| 车头方向 | 每个采样点的车头角度，或可换算的姿态 | 建议提供 | 可从运动估算，但倒车、原地转向无法准确还原 |
| 作业任务 | 任务号、订单号、设备 ID、托盘 ID、取货位、目标货位/卡车、任务时间 | 装卸关联必须 | 无法确认某台叉车在为哪个订单搬哪托货 |
| 托盘初始状态 | 起点时刻托盘在哪个货位、叉车或卡车上 | 载货回放必须 | 从中间时段进入、拖动时间轴时会出现载荷错误 |
| 取放交接记录 | 时间、托盘 ID、执行设备、交接前/后归属 | 载货回放必须 | 只能显示空车或明确标记的示意货物 |
| 货叉高度/装卸阶段 | 时间、高度或动作开始/结束时间 | 精确取放动作必须 | 可以生成示意抬叉动画，但必须标为推算 |
| 卡车位置/门状态 | 时间、位置、朝向、进出场、门开度 | 离场效果必须有轨迹，门状态可选 | 只知道“发车”不能还原上路路线；缺门传感器时可做示意开关门 |
| 关键事件 | 唯一事件 ID、发生时间、设备、类型、说明、故障关联 | 时间轴标记必须 | 故障等事件不能靠动画反推为真实事实 |
| 场景映射 | 业务货位/月台编码、地图版本、坐标标定 | 必须一次性确认 | 即使数据格式正确也可能错位或穿模 |

不要求上游提供帧率、发光颜色、轨迹材质、跟随相机参数、UE 模型路径、Actor 名或组件实例索引。它们属于项目表现与场景映射。`modelCode`、`attachmentSlots` 的具体尺寸和映射可由项目侧补齐；业务方优先提供车型、定位标签安装点、实际托位编号和机械尺寸。

## 二、查询与范围语义

建议分成两次读取（这里只约定数据，不代表已经存在这些接口）：

1. 传入 `warehouseId + startUtc + endUtc`，得到订单索引样例结构。返回区间内发生过作业的订单，包括开始时间早于查询起点但区间内仍有作业的订单。无数据返回空数组，不再返回固定测试订单。
2. 选择订单后，传入同一时间段和 `selectedOrderId`，得到回放明细。

按之前约定，`scope=WAREHOUSE_INTERVAL` 表示显示该时间段本仓库的全部回放设备，选中订单用于关联和突出显示，不能把其他设备全部过滤掉。样例的 `FL-002` 即是没有参与该订单的待命设备。设备范围仍以人工叉车和装卸卡车为主。

有分页时 `nextCursor` 标识后续页；各页应来自同一查询快照，设备、事件和订单按 ID 去重。本文样例一次返回完整数据。`complete=true` 只代表交付完整，不能代替轨迹精度或数据核验。

## 三、时间约定

- 统一传 UTC ISO 8601：`2026-11-09T17:00:00.000Z`。它对应洛杉矶当地 `2026-11-09 09:00:00 PST`。页面显示时区为 `America/Los_Angeles`，不能全年固定减 7 小时。
- 查询时段至少 3600 秒。业务事件使用半开区间 `[startUtc, endUtc)`，避免相邻区间重复事件；设备轨迹允许在 `endUtc` 包含一个边界状态，用于插值和停在最后一帧。
- 每条轨迹时间严格升序；同一设备同一时间有冲突值时，要说明修订/去重规则。事件同毫秒可有多个，用 `sequence` 确定顺序。
- 使用设备采集/事件发生时间，不使用数据库入库时间。定位、任务和装卸系统需要对时，或提供已知时间偏移，避免叉车已离开而托盘才交接。
- 查询起点必须能恢复当时状态：包含已经在车上的托盘、正在故障中的设备、尚未完成的任务。若故障跨越起点，在 `initialState.activeFaults` 提供原故障 ID、设备、故障码、真实开始时间和说明；区间内的恢复事件可引用该故障 ID，不能凭空生成一条发生在起点的故障。
- 真实历史播放到选择区间末尾就停止，不能将短轨迹循环补成一小时。中途到达的设备在出现前 `present=false`，驶离后为 false；设备离线不等于已经离场。

## 四、坐标、轨迹与动作

### 坐标标定

样例使用米制局部坐标。真实交付请说明原点、XYZ 正方向、地图版本、角度零点和正方向，以及定位点在车体上的安装位置。二维定位可以补充楼层/地面标高，不能把未知层高随意填为另一层的零点。若是经纬度，另给经纬度基准和高度基准，不能直接填入 `positionM`。

项目实际回放当前使用 UE 世界厘米、绕 Z 轴的 yaw。对接时由适配层进行单位换算、轴交换/旋转、平移和模型 pivot 修正。请提供至少 3 个分布合理、非共线且能在场景上识别的对应点用于标定与检查。业务地图与 UE 场景的版本必须对应。

`headingDeg` 指车头朝向。叉车倒车时车头和速度方向相反，不能直接用位移方向覆盖真实朝向。可选补充档位或前进/倒车标记，供缺少朝向的区间判断。

### 采样与数据质量

建议先拿实际定位系统现有频率的一小时完整数据评估。可用 1～5 Hz 作为首批样本的参考，快速转弯和装卸阶段需要保留更密的有效采样；不要求服务器输出 60 Hz。静止段可压缩成起止点，但转向、抬叉、装卸、出入场、故障状态变化的时间点不能丢。

`quality`：`measured` 实测、`estimated` 推算、`missing` 缺失、`sample` 样例。缺失的位置应标明缺失并用 null，不能填 `[0,0,0]` 冒充实测。若单个字段是推算，应单独补充该字段的来源标记，或将整条样本保守标为 estimated。`isTest=false` 也不代表每个定位字段都经过核验。

长间断、瞬移、越界点不能直接插值成穿墙直线；后续适配时需确认保持最后可信位置、隐藏或明确标记推算的策略。轨迹平滑要受仓库通道边界约束，不能为追求圆滑切过货堆。样例的稀疏转弯点仅解释格式，不是现成可安全行驶的场景路径。

### 托盘交接与抬叉

`initialState.palletStates` 给出起点归属；`PICKUP_COMPLETED` 与 `DROPOFF_COMPLETED` 的 `fromHolder/toHolder` 给出归属变化，构成唯一状态链。`eventBoundary=BEFORE_START_EVENTS` 明确快照表示起点事件应用前的状态；进入回放时，恰好 `startUtc` 的事件仍要应用一次。seek 到任意时刻 t 时，从初始快照开始，按 `(timeUtc, sequence)` 应用 `startUtc <= timeUtc <= t` 的交接，包括恰好 t 时刻的交接，不能只按曾经播放过的事件累计。

同一托盘同一时刻只能有一个归属。装卸事件必须引用存在的任务、设备、托盘、货位/挂点，且前归属要与上一状态吻合。卡车驶离后，附着托盘随卡车隐藏；不需要再复制一个地面托盘。

本样例的每个 location 表示一个具体托盘承放位置。若一个业务货位包含多托或上下堆叠，需要独立的托位/层位 ID 及其托盘底面位置，不能全部套用同一个库位中心点。设备挂点公式为：托盘世界位置 = 设备位置 + 按车头角旋转后的局部 offsetM + 货叉抬升量（仅 usesForkHeight=true 时沿 Z 叠加）。

样例的交接位置可核对：取货时叉车 `[8,10,0]` 加货叉局部偏移 `[2,0,0]`，等于货位 `[10,10,0]`。放货时叉车 `[74,50,0]` 加偏移和抬升 1.2 米，等于卡车 `[80,50,0]` 加车厢偏移 `[-4,0,1.2]`，两边均为 `[76,50,1.2]`，避免归属切换时跳动。真实偏移必须按实际车型重新标定。

业务系统的“取货完成”可能是扫码完成、离位完成或实际夹取完成，要先明确时间语义。样例用它表示托盘已被货叉承托，随后抬升；不能默认所有系统都有同样定义。若有高度传感器，按实测高度播放；只有业务节点时只能补示意动作。

## 五、枚举与必填边界

| 字段 | 本样例支持的约定 |
|---|---|
| `deviceType` | `MANUAL_FORKLIFT` 人工叉车、`LOADING_TRUCK` 装卸卡车；其他类型后续按实际数据扩展 |
| `status` | `IDLE` 待命、`MOVING` 空载移动、`PICKING` 取货、`CARRYING` 载货、`DROPPING` 放货、`WAITING` 等待、`FAULT` 故障、`DEPARTING` 发车、`LEFT_SITE` 离场 |
| `events.type` | `PICKUP_COMPLETED` 取货交接、`DROPOFF_COMPLETED` 放货交接、`FAULT_STARTED` 故障开始、`FAULT_CLEARED` 故障解除、`TRUCK_DEPARTED` 发车、`TRUCK_LEFT_SITE` 驶出区域 |
| `holder.type` | `location` 货位/工位、`device` 设备挂点 |
| `quality` | `measured`、`estimated`、`missing`、`sample` |
| `severity` | `info`、`warning`、`error` |

基础必填字段按注释样例提供。条件字段：叉车的门开度、卡车的货叉高度为 null；无任务的 `taskId` 为 null；非装卸事件的 `palletId/fromHolder/toHolder` 可为 null；非故障事件的 `faultCode/relatedEventId` 可为 null。未知采样值用 null 并说明来源，不能用 0 代替未知。未知新增枚举应先建立映射，不应静默当正常状态。

`positionReference`、`modelCode`、托盘尺寸、设备挂点是一次性的主数据/项目配置，不需要每个轨迹点重复。模型挂点不是要求业务系统采集的新传感器信号。

## 六、与当前代码的对应关系

本次核对了工作区代码及主项目对应文件，关键解析逻辑一致。以下为现有演示格式的事实，不是让上游按它建设真实接口：

| 当前实现 | 真实接入需要的适配 |
|---|---|
| 只接受 `TEST-OUT-001`～`TEST-OUT-004`，所有订单加载同一文件 | 以实际时间和订单查询数据，区分测试/真实来源 |
| 固定 18 条轨道：5 叉车、3 卡车、10 个货物 | 按真实实体创建回放对象；上游不需要凑够固定数量 |
| 数据周期为 2461 秒，播放按周期取余，事件随之重复 | 按真实起止时间播放，不重复构造事件 |
| 每条轨道必须首帧为 0、末帧为周期末，首尾位置/朝向/归属/可见性一致 | 真实轨迹允许任意开始/结束位置，首尾不必相同 |
| `keys` 用长度为 10 的数组，实际读取前 8 个字段 | 具名字段转换为内部关键帧；无需上游发送数组下标归属 |
| 世界坐标为厘米，货物附着时变成父设备局部偏移 | 坐标标定、设备参考点修正、托盘归属与挂点映射 |
| 事件只展示在列表/时间轴，不自动抬叉、取放或开门 | 由真实姿态/交接记录构建状态，缺失动作明确标记推算 |
| `route` 虽解析，但移动与轨迹实际都由 `keys` 生成 | 交付有时间的轨迹采样，单给一条无时间折线不够 |
| 硬编码 `isTest=true`，JSON 元数据不能解除测试标记 | 改为随核验后的数据来源展示，避免真实/测试混淆 |
| `sourceInstances` 绑定场景 Actor、组件和实例索引 | 项目侧维护货位/月台到场景的映射，上游只提供业务 ID |

## 七、第一批真实样本建议

提供任意一个有实际作业的一小时时间段，包含至少一台人工叉车、一台装卸卡车、一次完整取货与放货；若有故障/恢复、发车和多个设备交叉作业，一并提供。选择区间中间一个时刻核对已载货状态，能帮助验证拖动时间轴是否正确。

同时附上定位系统原始坐标说明、仓库平面图上的对应点、设备/货位/月台编码表、时间语义和采样频率。若当前系统没有连续定位、托盘标识或货叉高度，请直接写“无此数据”；先确认真实可还原的范围，再决定哪些动作只能做示意。

收到数据后才能检查实际场景对齐、路径穿模、取放交接、离场、倍速/暂停/跳转、事件时间轴和跟随视角。本次样例校验不等于这些真实数据功能已实现或已经验收。
