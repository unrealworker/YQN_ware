## 先确认对象

- 以原始 DXF 的嵌套 INSERT、实际轮廓和装配手册区分主机、固定滑槽、移动分播小车、在用料框车、备用空车、供包设备和绘图符号。
- 用户说的“五排”不是独立设备数量依据。按最新说明检查其中是否为可替换空货仓，不把所有蓝色长面都当输送带。
- 带叉矩形目前被误建成带屏工作桌；GHS 斜坡复用时的轴向和比例也需逐对象纠正。
- 无连续 CAD 接驳证据的间隙不得靠最近距离自动连带。人工取货、人工推车需在动画中明确表达。

## 依据

- 本地《96格口木马装配指导书-V1.0(2).docx》提供主链、升降小车、固定滑槽与独立带刹脚轮料框车的机械依据。
- 厂家产品及智能播种页面提供业务定位；厂家申请的 WO2024119631A1 提供供货扫码、空车接货、水平运行、升降投递、容器在位和异常格口的原理依据。
- 专利实施例不等于 MPR 实机配置；没有现场操作说明支撑的换车时序、节拍和容量明确标为演示参数。
- 96 格手册每车 3 列 × 4 层；MPR 8 列/15 列平面不得强行套用，车框分组继续核原 CAD。

## 工作流

有界供货队列 → 人工/自动接驳（按源图）→ 扫码与目的地判断 → 同一包裹转至空托盘 → 水平运行、升降 → 固定滑槽入箱 → 整组料框车满载 → 停止新供货并完成在途事务 → 本机停稳 → 整车带货退出 → 空车入位与确认 → 新代次开始供货。

其中本机停稳、示意人工搬运时间、所有格口达到演示件数容量才换车，属于展示策略。订单齐套与物理满载分别定义，不用计数清零伪装实际搬走，不声称已接 WMS/PLC。

## 分工与验证

1. CAD 全覆盖审计、局部输送修复与原位标记。
2. 可动料框车资产与静态滑槽拆分；保留原始箱位、材质和外部几何。
3. 纯 C++ 供货、预占、车代次、换车状态机及确定性测试。
4. UE 展示、人工交接/推车、HUD、既有相机联动。
5. 真实渲染下固定机位检查供货、投递、满车退出、空车进位全过程；检查邻机与通道、守恒、暂停/复位/倍率、缺车禁止投料；记录原生运行帧率。
6. 现有地图原位小范围应用与独立重载，按 Actor GUID/实例逐项核对保护范围。分别提交已完成且验证的独立修复和功能，不提交缓存、备份与其他任务改动。
