# UE 5.8.4 升级与完整回归计划

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Independent plugin audits can run in parallel; integration and builds remain sequential.

**Goal:** 将 GHS 仓储项目从 UE 5.4.4 升级到本机 UE 5.8.4，保留现有外观、业务交互、追溯、像素流和编辑工具功能。

**Architecture:** 在独立 Git 工作树适配和验证，不让新版本保存原项目资产。继续使用 UE 5.8 Legacy PixelStreaming，并移植现有项目补丁；本次不额外引入 PixelStreaming2 协议迁移。

**Tech Stack:** UE 5.8.4 CL58902052、MSVC 14.44.35229（安装目录 14.44.35207）、Windows SDK、项目 C++、CEF Web UI、Node 像素流服务、.NET 启动器。

**Spec:** 用户要求“升级到UE5.8，但必须保证所有功能正常”；功能范围以当前源码、测试及项目既有交互为准。基线提交 `2bc8d04`，原项目 `D:\UEPro\Test`，独立分支 `codex/ue58-upgrade`。

## Global Constraints

- 升级期间原项目保持 UE 5.4.4；升级资产必须是独立副本，不能用 Content junction 或硬链接。最终按用户“以后就用5.8打开本项目”指令，将已验证升级快进到原项目，保留 Git 基线 `2bc8d04` 及 UE 5.4 引擎供回退。
- 保留材质、场景布局、双托盘、AGV、车辆、地面手动修改、现有数据及 UI 风格。
- 继续关闭 Lumen/光追，不借升级擅自改画质策略；记录新引擎实际渲染设置。
- 不用禁用插件、删测试、关交互或忽略失败来获得“通过”。
- 完成验证的独立改动使用中文本地 Git 提交；未验证项目留在升级分支，不覆盖 master。
- 只保留一份当前升级构建，日志/报告写 Saved/UE58Upgrade；避免重建多份历史测试包。
- 这轮不修改服务器正在使用的程序。用户要求仅本地验证，最后决定自行接手后续体验；停止额外验收，未完成项目不记为通过。

## Review Focus

1. 屋顶闭合时标签隐藏、选择遮挡及设备定位顺序；用屋顶原生与真实场景脚本验证。
2. 回放退出/中断/跨页时设备和 UI 恢复；用 session、POI、跟随与完整回放脚本验证。
3. CEF 输入、中文、图表、面板收展、焦点与浏览器像素流输入；两端分别验证。
4. GPU/材质默认值变化造成的外观和帧率回退；固定分辨率与场景状态对照，线程耗时不可相加。
5. Editor 编译成功但 Shipping 丢失插件或 NonUFS 数据；完整 Cook/Package 后重新运行并连接浏览器。
