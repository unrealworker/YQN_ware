# Peer-stream 服务器对比部署计划

> 执行方式：本轮直接实施和验证，用户已授权部署并自行测试；不再等待方案确认。

**目标：** 在阿里云 10.100.185.161 部署 inveta/peer-stream，使用当前 UE 场景和可达域名，保留原方案供比较。

**依据：** 用户最新指令“你直接用它这一套部署在服务器上把，我自己来测试对比”。此前优化功能实施暂停。

**架构：** 保留固定域名的原入口；为 peer-stream 使用独立 loopback 信令进程及 /peer-stream/ 对比入口。仅在必要时给原服务增加受限反向代理入口，媒体仍由浏览器与 UE 的 WebRTC 连接传输。使用已固定并校验的 upstream SDK/信令，只做部署适配，不替换解码器或修改场景。

**约束：** 同一当前 UE EXE；按用户最新指令统一1920×1080、固定60 FPS上限、H264、1/8/24 Mbps、MAINTAIN_RESOLUTION、同一编码质量与低延迟参数；UDP 使用已开放的50000–50199。关闭原方案按人数自动调帧，保持两方案60目标。两个入口共用10人接入上限，不宣称支持10人性能。保留其余用户配置；管理接口只允许本地令牌。两个方案比较时一次仅开一个，等待旧实例回收。
