## 机械呈现

现有长机内部假多层皮带和实心端柜遮挡真实运动关系。保留固定侧架、格口、滑槽和料框，换成开放上下导轨、端框、移动立柱及短带托盘。新模型使用独立资源目录，不能覆写其他关卡共享的原设备包。

每台演示 4 个载具，以 0、1/4、1/2、3/4 环路相位共用主链，不相互超越。立柱沿水平长圆环路运动，托盘沿各自立柱升降，短带向当前侧的固定槽卸料。商品随承载面运动，到列和层均对准后才进入槽与箱。固定格口、滑槽和箱不旋转、不升降。

轨道尺寸、格口中心、滑槽入口/出口、箱底/箱沿从保留的场景模型提取为厘米坐标配置；载具路径为现有外廓内的演示拟合。变换只应用一次，明确 Blender 与 UE 的 Y 轴转换。源图要求小车对滑槽任意升降间隙大于 20 mm；本次检查视觉无穿插和有效承载路径，不以 AABB 采样宣称实际制造间隙达标。这是工作流程动画，不是制造或动力学校核。

## 行为与状态

`EmptyReturn → Scan → LoadedTravel/Lift → Unload → EmptyReturn`。端部载入一件演示商品，赋予唯一 `ParcelId` 和 `Destination{Side, Column, Level}`。目标队列可重复遍历两侧所有列、层，不把目标编号当真实订单。

主链行走与托盘升降可同时发生；到站时若高度未就绪，整条共同主链等待。扫码、卸料、满格也使用可解释的停链演示策略。卸料完成才增加命中格口计数并释放载具，短带动作和包裹路径应在视觉上连续。

演示包裹为 22 × 16 × 5 cm，默认 `BinCapacity=3`、`CollectSeconds=12`、`AutoCollect=true`，速度为 1×/2×/4×，这些均不表示真机参数。自动取箱在首次入箱后计时，重新开启时重计完整间隔。格口 `Reserved>0` 时拒绝手动取箱，过期自动取箱等卸料完成后再执行，避免运动包裹目标堆高突然改变；过期预留事件不阻断时间推进。关闭自动取箱后，满格停链等待；手工“清满格”或模拟取箱会累计已取数量，之后继续卸料。此操作仅改变演示占用，不声称执行真实换箱。

纯 C++ 核心独立于 UE Actor、物理、时钟和资产，不依赖随机状态。核心处理事件边界，不能因低帧率或高速跳过扫码、到站、到高、卸料或取箱事件。非法配置或非法时间步返回失败并保持既有状态。

必须满足：

- 活动 `ParcelId` 唯一，跨机记录以设备 ID 限定，复位后属于新的演示周期。
- `Occupancy + Reserved ≤ Capacity`。
- `Spawned = Completed + Active`。
- `Completed = Σ Occupancy + Collected`；格口计数之和与总计一致。
- 暂停冻结相位、高度、计时与计数；复位清空所有演示状态，暂停并恢复 1×。
- 等总模拟时长下，大步与小步产生相同结果；拒绝时间步不允许局部推进。

## UE 集成与数据

`MPRSorterSimulationActor` 持有内嵌、可序列化的布局 JSON 与显式资产引用，运行不读取 `Saved`。按原 Actor GUID、组件、实例索引和源句柄校验目标绑定，先完成 22 台范围预检再写关卡。固定体、移动立柱、托盘和包裹分开呈现，集中更新可变实例，避免每件包裹生成独立 Tick Actor。

新 `MPRSorterHUDWidget` 只在目标 MPR 中显示：开始/暂停、复位、速度、定位设备、模拟取箱、清满格及统计/等待原因。控制对全部 22 台生效，设备切换、定位和统计针对选中设备，标题下明确写出全场作用域。定位复用既有相机能力，不改变 GHS 通用 HUD 或输入语义。

Actor 提供 `SetSimulationPlaying`、`ResetSimulation`、`SetSimulationRate`、`SetAutomaticCollection`、`ClearFullBins`、`FocusMachine`。诊断报告通过 `GetSimulationReportJson`；人工时间推进 `AdvanceSimulationForDiagnostics` 只允许 `-TwinDiagnostics` 环境，不能变成普通运行控制入口。
