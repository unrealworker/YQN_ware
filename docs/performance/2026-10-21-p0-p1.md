# GHS 仓库 P0 / P1 性能优化与打包修复

目标：Windows 本地运行，1920×1080，朝稳定 60fps 优化。此轮保留现有场景画质、页面设计和交互动画；像素流端到端性能不在本次测量范围。

## 打包修复

本次最新打包失败的直接原因是 `No target name was specified on the command-line`。UE 将原游戏目标名 `Test` 解析为构建配置，导致没有剩余目标名。游戏目标改为 `TestGame`，`DefaultGame.ini` 明确选择该目标；项目文件、C++ 模块和地图名称不变。Game 和 Editor 目标均固定本机已安装的 MSVC `14.38.33130`。

优化前基准与优化后项目均完成 Win64 Development 的 build、cook、stage、pak、archive。优化后打包未传显式 `-target`，验证了项目设置能够正确选择目标。`Saved/PerformanceP0P1/optimized_package.log` 记录 `BUILD SUCCESSFUL` 和 `ExitCode=0`。

可运行产物：`Saved/PerformanceP0P1/OptimizedBuild/Windows/TestGame.exe`。分发时保留整个 Windows 文件夹，不能只复制这个启动文件。

## 改动

- P0：增加显式 `-TwinPerf=<label>` 性能路线、实际 CPU / GPU CSV 测量、配置一致性校验和重复测量汇总。普通启动不运行测试路线，Shipping 不包含驱动。
- 场景数据：缓存 Actor 注册表，监听增删与关卡变化；实例复查分摊到每帧最多 128 项，仅重建变化记录。保留低频全量发现兜底、动态复制设备、实时货物拾取与定位。
- 原生 HUD：POI 候选筛选、排序和文本按变化或 100ms 刷新；可见点仍逐帧投影。选中模型包围框投影复用，字体和几何缓存。
- 页面：收到数据后复用索引和统计，先比较当前页面依赖再生成 HTML。面板完全滑出后暂停数据推送与页面刷新，展开前应用最新选择和快照。
- 正常运行关闭详细诊断报告；`-TwinDiagnostics` 可显式恢复验收信息。保留 Browser 60Hz、320ms 页面过渡、420ms 可逆面板滑动及搜索焦点和滚动位置。

实例数量、网格或组件结构发生变化时，仍可能同步重建对应组件；本次预算缓存主要优化稳定场景的重复检查，不承诺任意规模动态导入都没有瞬时成本。

## 测量条件

硬件为 i9-14900HX、RTX 5060 Laptop GPU、32GB 内存，UE 5.4.4，Win64 Development。对比两边均使用相同地图、资产、版本 2 路线、1920×1080 离屏渲染、100% 渲染比例、不启用动态分辨率、关闭垂直同步且不限制帧率。每轮预热 15 秒，记录 90 秒，含两次 45 秒路线；优化前后各三轮。

路线包含远景、全部 POI、旋转、AGV / 叉车详情、货架、真实物料点击、面板收展和七个页面切换。采样期间不运行另一个 UE 编辑器或构建任务。所有配置差异由脚本检查；原始 CSV 保留。

## 三轮实测结果

下表为每种版本三轮结果的中位数，单位 ms；耗时越低越好。

| 指标 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 主线程平均耗时 | 2.366 | 1.809 | 降低 23.5% |
| 主线程 P99 | 4.580 | 3.347 | 降低 26.9% |
| 整帧平均耗时 | 11.331 | 11.508 | 增加 1.6% |
| 整帧 P95 | 15.269 | 15.391 | 增加 0.8% |
| 整帧 P99 | 17.279 | 17.336 | 增加 0.3% |
| GPU 平均耗时 | 11.759 | 11.924 | 增加 1.4% |

| 轮次 | 优化前整帧平均 / P99 | 优化后整帧平均 / P99 | 优化前 / 后超过 33.33ms 的帧数 |
| --- | ---: | ---: | ---: |
| 1 | 11.331 / 17.279 | 11.508 / 17.336 | 3 / 0 |
| 2 | 11.562 / 17.697 | 11.662 / 17.602 | 3 / 1 |
| 3 | 11.105 / 16.681 | 11.284 / 17.061 | 3 / 0 |

三轮累计超过 33.33ms 的卡顿由 9 次降为 1 次。基准前两轮约每 30 秒出现一次 UI 尖峰，第一轮优化版的 UI 独占耗时均值从 1.121ms 降至 0.398ms，最大值从 56.10ms 降至 1.91ms。CSV 支持周期 UI 开销显著下降，但不足以把每个尖峰精确归因到某个子函数。

**P1 降低了 CPU / UI 开销和明显卡顿，但没有整体帧率提升的证据，也未达到严格稳定 60fps。** 优化版仍有约 1.19%–1.85% 的帧超过 16.67ms。GPU 耗时约为主线程的六倍，远景与货架区域仍更重；后续应针对 GPU 渲染成本单独分析。此轮没有继续实施 P2 画质或场景调整。

原始证据为 `Saved/PerformanceP0P1/Baseline01_*` 至 `Baseline03_*`、`Optimized01_*` 至 `Optimized03_*`。`matrix_summary.json` 已校验六份运行元数据一致；三轮波动范围保留在该文件中。

用户于收尾阶段明确要求“先优化到这里”，因此已主动终止 30 分钟长测。`OptimizedSoak_20261021_033022` 属于**取消的非完整记录**，不参与性能比较，不能作为长期稳定性或无内存泄漏的证明。
