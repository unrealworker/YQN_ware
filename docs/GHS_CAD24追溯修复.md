# GHS CAD 2.4 追溯修复（2026-11-26）

## 问题与处理

整仓布局更新后，追溯仍引用旧地堆分组和实例下标。实际启动报错为“回放货位或月台已变化: BP_GHS_InstanceGroup_C_17”。旧路线还进入了新货架范围，旧避障检查又因只识别 `GHS_V2_Rack` 前缀而漏掉了新货架。

新版回放文件使用 CAD 编码、当前场景清单哈希和实例姿态绑定取货地堆、装卸门。启动时先唯一解析全部目标，再隐藏对应实例。实例下标重排不会造成错误取货；布局、姿态或身份不一致会停止启动并显示原因。退出恢复原有实例、设备、镜头与屋顶状态。

五台叉车的取货点及运输路线按当前地图重新生成，货物使用现有中档双层地堆的尺寸与朝向。装卸车的出场和返场路线也重新检查。原 20 号月台受到新货架影响，第三辆回放卡车改用可通行的 22 号月台。

新地堆取货方向使托盘无法按原朝向在车厢内并列摆放。装卸流程增加了在月台前落托、绕行、重新插叉的换向步骤，卸货时逆向执行，避免货物瞬移或互相重叠。回放单层中档托盘补充侧叉净空，保留外廓、高度、蓝托盘和白色箱体材质；原仓库双层地堆与地图不需要改动。

## 后续布局变更后的更新流程

1. 在已保存的 GHS 编辑器地图运行 `Scripts/ghs/replay_probe_scene.py`，提取当前实例、墙体和通道货架实际网格。
2. 运行 `replay_plan_routes.py`、`replay_truck_routes.py`、`replay_build_timeline.py` 生成路线与回放文件。选择的 CAD 编码和月台必须存在且具有有效净空。
3. 运行 `replay_validate_static_actions.py`、`replay_validate_timeline.py`、`replay_validate_turning.py`，检查当前地图和清单指纹、连续运动包络、装卸动作及货物所有权切换。使用 Blender 运行 `replay_validate_cargo_contacts.py` 检查全部货物和叉车接触部件的实际三角网格。
4. 编译后运行 `GHS.Replay` 自动测试，并在独立的 `-game -RenderOffscreen -TwinDiagnostics` 进程运行 `verify_order_replay_runtime.py`。检查实际画面以及播放、跳转、暂停、退出恢复结果。

探针与审计输出保存在 `Saved/OrderReplay/`，不能用旧探针的通过结果验收新布局。回放数据仍明确标为测试订单演示，不代表真实订单作业记录。本次只完成本机工程及验证。
